# 如何定义和评估两个策略的对战

## 博弈是什么

本项目用部分可观测马尔可夫博弈（POMG）描述游戏：

\[
\mathcal G=(\mathcal S,\{\mathcal A_i,\mathcal O_i,Z_i,r_i\}_{i=1}^2,P,\rho_0,H).
\]

- \(s_t\in\mathcal S\) 是引擎完整状态；当前接口没有导出完整状态。
- 玩家同时选择 \(a_t^1,a_t^2\)，引擎按 \(P(s_{t+1}\mid s_t,a_t^1,a_t^2)\) 推进一帧。
- \(o_t^i\sim Z_i(\cdot\mid s_t)\) 是第 \(i\) 名玩家的观测。
- \(\rho_0\) 是初始化分布。当前实验固定场景和角色，配置列出游戏种子。
- \(H\) 是评估帧数上限。当前配置为 7200 模拟帧。
- 首次击倒结束对局，胜方奖励为 \(1\)，负方为 \(-1\)，同时击倒为 \(0\)，中间帧奖励为 \(0\)。这里使用不折扣的奖励总和。

策略可以依赖观测与动作历史：

\[
\pi_i(a_t^i\mid h_t^i),\qquad
h_t^i=(o_0^i,a_0^i,\ldots,o_t^i).
\]

接口不要求策略无记忆。有限状态机、行为树、Lua 协程和循环神经网络都可通过独立的 `Policy.act(observation)` 实现。
每局为两名玩家各创建一个策略实例。随机策略必须使用传入的私有种子，不能共享全局随机数状态。
本次接入的树策略和社区规则子集都是确定性的；测试中的随机策略用于核对种子隔离。

## 观测和动作

当前观测为己方与对手的位置、生命、灵力比例、动作编号、腾空状态、命中停顿、角色编号和朝向，以及带攻击判定的对手对象的位置与速度。
所有字段都来自当前已完成的模拟帧。它包含人类无法直接从画面准确读出的内部数据，所以属于使用内部状态的策略比较。
双方按同一字段规则获得观测，不向策略暴露对手本帧刚选出的动作或游戏随机数种子。

动作包含水平轴、垂直轴和 A、B、C、D、切卡、符卡六个按钮。环境收到双方动作后才推进一帧。
共享内存命令收到确认并不代表该帧已完成；适配器还等待目标帧号和暂停状态。
丢帧、对象溢出、场景错误或接口超时使整批评估失效，不能记为某个策略失败。

`TimeStep` 区分游戏结束与外部截断。当前原生适配器通过重新启动游戏创建新对局，不提供内存快照回滚。

## 胜率的分母

同一游戏种子下，先让策略 A 使用 1P、B 使用 2P，再交换位置。两局合为一个配对区组。
角色当前随座位固定为 1P 魔理沙、2P 灵梦，因此这里评估的是这两个角色与座位组合的均衡比较，不能解释为某个固定角色的胜率。
配对时，逻辑玩家的私有策略种子跟随策略交换。

只统计两局都完整运行的区组；另外报告计划区组数、完成区组数、错误局数和缺失局数。
如有区组失败，剩余结果只是成功区组的描述，不能无条件外推到原计划总体。

设已完成区组中的总局数为 \(N\)，A 的胜、负、同时击倒、超时次数分别为 \(W,L,D,T\)：

\[
p_{\text{win by }H}=\frac{W}{N},\qquad
p_{\text{eventual win}}\in\left[\frac{W}{N},\frac{W+T}{N}\right].
\]

收益矩阵中每个单元的可确定范围为：

\[
u(A,B)\in\left[\frac{W-L-T}{N},\frac{W-L+T}{N}\right].
\]

超时局的未来结果未知。需要给 PSRO（策略空间响应预言机：在策略集合上求解博弈并加入新响应策略）提供单一收益值时，必须先规定截断收益规则；本评估器不默认为零。
无超时的完整结果可直接提供上述终局收益的均值。
评估支持自我对战，收益矩阵包含对角线。

置信界以独立区组为单位，不能把交换位置的两局当成两次独立样本。
若 \(B\) 个区组来自独立的种子抽样，Hoeffding 界的半径为：

\[
\epsilon=\sqrt{\frac{\log(2/\alpha)}{2B}}.
\]

将胜率下界减去 \(\epsilon\)、上界加上 \(\epsilon\)，再裁剪至 \([0,1]\)。这是每个矩阵单元的保守区间，不是整个矩阵的联合置信区间。
默认三个固定种子用于可复现的对照实验；它们不构成对真实对局分布的随机抽样证明，不能依据三组结果宣称总体胜率已准确估计。

## 代码与运行

| 文件 | 责任 |
| --- | --- |
| `src/soku_rl/pomg.py` | 策略、双人批量环境和时间步接口，不依赖 Windows。 |
| `src/soku_rl/strategies.py` | 根据配置创建策略，生成配置与实现指纹。 |
| `src/soku_rl/community_rules.py` | 有记忆的社区规则子集。 |
| `src/soku_rl/evaluation.py` | 生成对局计划、运行策略、统计配对结果。 |
| `tools/game_batch.py` | 复用已验证的启动和同步代码，管理自己创建的游戏进程。 |
| `tools/evaluate.py` | Hydra 入口、运行文件指纹、结果持久化。 |
| `config/evaluation.yaml` | 继承已有策略配置的正式对战配置。 |

在装有依赖的 Windows Python 环境中运行；Linux 上使用已配置的 Wine 包装程序运行同一入口：

```powershell
.\.venv\Scripts\python.exe tools/evaluate.py
```

默认五个策略，每个种子包含 10 个异策略组合和 5 个自对战组合，每个组合交换位置，两局一组；三个种子合计 90 局。
结果路径已存在时拒绝覆盖。再次运行应通过 `output=...` 选择新文件。

结果保存完整计划、策略指纹、游戏文件与模块指纹、每局种子、座位、角色、初末状态哈希、结果、规则触发次数和耗时。
每批结束后原子替换报告；遇到异常写入错误结果并终止实验。计划中未运行的局仍保留为缺失，不能被隐藏。

原来的 `tools/baseline_tournament.py` 仍可运行，配置格式继续有效；需要胜率和收益矩阵时使用新入口。

该入口已完成[五个策略的 90 局正式评估](community-evaluation.md)。
