# 面向双人学习的环境改造

## 目标与当前状态

目标是让策略使用人类能感知的信息和能执行的按键，同时保留强化学习算法的优化能力。环境必须提供图像和结构化状态两种观测，并支持单局双人控制、多局并行以及公开算法的训练循环。

已实现控制时序、图像和经过过滤的状态观测，以及 PettingZoo 单局接口。状态观测现在包含粗略轮廓遮挡判定。完整真实游戏验收和基础训练循环尚未完成。旧的诊断数值观测直接来自内存，不能标记为符合本规范。

最终公共接口为 PettingZoo `ParallelEnv`。`possible_agents` 固定为 `player_0`、`player_1`；双方同时提交按键。多环境层组合这些双人对局，公开算法所需的转换放在算法适配层。

## 用户确认的控制规则

- 游戏模拟以每秒 60 帧计时，计算机运行得更快不会改变这个时间尺度。
- 每 3 个游戏帧接收双方各一次决策。
- 在帧编号为 \(t\) 的观测之后提交的按键，在 \(t+12\) 到 \(t+13\) 的状态转移中首次生效。
- 按键状态保持到下一条到期命令，不提供自动连招或绕过原游戏输入处理的动作。
- 每个新对局清空待执行命令，并将当前按键恢复为全部释放。
- 配置项为 `episode.decision_frames` 和 `episode.latency_frames`。3 帧和 12 帧是本项目选定的训练约束，不是对所有人类反应能力的测量结论。

控制延迟只计算一次。不能同时延迟观测 12 帧、再延迟按键 12 帧，却仍报告 12 帧延迟。

## 模块职责

| 模块 | 必须承担的职责 | 不应包含的职责 |
| --- | --- | --- |
| 原生桥接模块 | 同步模拟帧、采集对应画面及可见性所需渲染信息、提交原生按键 | 选择策略、训练模型 |
| 单局环境 | 双方同时决策、控制队列、观测过滤与历史、奖励、终止与截断 | 对手策略、种群选择 |
| 多局环境 | 批量推进同一种单局逻辑，独立重置指定对局 | 重新定义动作和观测规则 |
| 算法适配 | 转换公开算法需要的数据形式、管理各方策略与样本 | 绕过观测过滤、缩短控制延迟 |
| 运行记录 | 保存配置、软件和游戏版本、种子、结果和诊断 | 向策略提供种子、内存哈希等隐藏信息 |

当前单局与多局共用 `Episode` 和 `DelayedControls`。多局推进遇到某局提前结束时立即停止该局，仍推进其他局。对局期限按游戏帧计算，算法步数按决策次数计算，二者必须分别记录。

## 状态观测的可见性约束

用户允许从内存读取状态，但要求限制可见性和精度。结构化状态不是引擎完整状态，也不能等同于 PettingZoo 的集中式 `state()`。

实施时必须逐字段确认来源：

| 信息 | 处理要求 |
| --- | --- |
| 角色及弹幕位置 | 转为屏幕坐标，量化精度；不可见时隐藏坐标及其他属性 |
| 物体是否可见 | 检查相机范围、渲染透明度、天气和遮挡；仅通过视口检查不构成可见性证明 |
| 速度 | 从已提供的历史观测估计，不直接公开内存中的瞬时速度 |
| 血量、灵力等界面信息 | 仅公开画面确实展示的部分，并采用与界面分辨率对应的精度 |
| 动作编号、攻击标志、碰撞框、剩余停顿时间 | 不进入策略观测 |
| 对手手牌、随机数、完整对象表、内存地址、状态哈希 | 不进入策略观测；界面公开展示的牌信息需另行逐项确认 |
| 不可见物体的历史位置 | 可以留在既有观测历史中，不能用当前隐藏状态刷新 |

所有策略必须经过同一个过滤模块。公共环境的 `info` 已移除种子、内存状态哈希和原始诊断数据。

### 粗略轮廓与遮挡

用户允许近似判定，不要求逐像素分割。状态模式不需要每步渲染。`visibility.py` 调用 `contours.py`，用角色椭圆和物体圆形估计轮廓，结合屏幕边界、透明度和重叠面积过滤观测。轮廓不使用攻击框或受击框。

配置统一放在 `episode.visibility`：角色宽 48、高 96，物体直径 16；尺寸按相机缩放转换到屏幕。角色以脚部为原点，物体以中心为原点。这些尺寸是初始假设，尚未完成不同角色、姿态和弹幕的截图校准。

算法在单位椭圆内的固定采样点估计剩余可见比例。被其他轮廓覆盖的采样点按其透明度衰减；屏幕外的点不计入可见部分。比例低于 `minimum_visible_fraction`（初值 0.25）时，不公开该对象的位置和朝向。隐藏物体不占用公开列表的槽位。局部重叠且剩余比例达到阈值时保留对象。

当前没有前后绘制顺序，因此重叠区域对双方都视为缺少可见证据。这会多隐藏对象，不能称为真实画面的精确遮挡结果。完全重叠的两个不透明角色会同时隐藏。背景前景物、超出圆形范围的特效、角色姿态变化尚未建模。原点在屏幕外的对象仍直接隐藏，即使其轮廓有一部分进入屏幕。

已取消“非晴天隐藏全部位置和血条”的临时规则。[游戏指南的天气说明](https://hisoutensoku-cn-wiki.vercel.app/GameGuide/weather.html)指出晴岚隐藏的是卡槽；这不能作为隐藏全部角色和血条的依据。当前状态不提供卡牌或实际天气编号；透明效果通过渲染透明度处理。天气粒子造成的画面干扰仍需截图验证，不能把这次规则调整当作全部天气视觉效果已通过验收。

## 图像观测约束

图像必须来自游戏实际渲染，不能用坐标绘制的示意图替代。图像与状态必须有可核对的同一模拟帧编号。采集失败必须报错，不能返回旧画面或黑图继续训练。图像分辨率、颜色通道、历史长度和玩家位置标识必须写入观测空间与运行配置。

## 验收证据

已执行 `python -m unittest discover -s tests -p 'test_*timing.py'`，5 项检查通过。检查覆盖 12 帧延迟、决策边界、重置清空队列、单局与多局时序相同、部分重置互不影响、期限不足一个决策间隔时停止。这些检查使用确定性替代后端，不能证明原生游戏、图像或训练已经通过。

尚需提供的证据：原生图像帧同步；不同天气及遮挡下的状态过滤；真实游戏单局和多局一致性；两种观测的空间检查；使用公开算法完成参数更新、保存模型和正常关闭资源的训练记录。只有这些证据齐全，才能宣布本次改造完成。
