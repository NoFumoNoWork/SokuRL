# 训练与交付验收

本清单对应用户扩展后的完整目标。写完适配代码、通过替代后端检查或完成一次参数更新，都不代表全部目标已经完成。

## 必须交付

1. 原生桥接与 Python 分层：单局双人 PettingZoo `ParallelEnv` 是公共接口，多局执行复用相同规则。
2. 图像与结构化状态两种观测。结构化状态允许读内存，但必须限制可见性和精度。两种观测都遵守每 3 帧决策、12 帧感知到按键延迟，参数可配置。
3. TorchRL、BenchMARL、OpenSpiel PSRO 和 NFSP 适配。可以根据同时行动、多个对局和真实游戏进程调整实现，不能把其他库的 NFSP 当作 OpenSpiel 接入结果。
4. 在服务器完成完整对局、连续重置、多局并行、生态接口检查。记录实际命令、配置、版本、结果与错误。
5. 运行基础训练并初步调参。记录采样量、更新次数、损失、参数变化、对局结果；不能仅用损失下降证明策略变强。
6. 获得有意义的可玩策略，保存模型及加载入口。用保留的评估种子，与已有规则策略对战，并分别统计胜、负、双重击倒和超时。
7. 保存动作回放及重放入口，录制真实游戏回放视频。记录起始配置和随机种子；原生 `.rep` 若不可用，必须明确说明所交付回放格式与局限。
8. 检查模块职责和接口，更新使用文档，清理本次临时调试文件。

## 对战结果必须说明的条件

已有规则策略读取过内部动作编号，并曾使用逐帧即时控制。新策略采用受限观测和控制延迟。评估必须写明规则对手是否保留旧权限，不能将不同权限的对局描述成同条件对比。

同条件规则对手需要适配受限观测。依赖被移除字段的规则必须明确修改或禁用，不能用伪造的动作编号冒充输入兼容。旧权限规则对手可以保留为另一个评估组，其结果应独立报告。

训练种子和评估种子分开；两个玩家位置分别评估。超时必须单列。有限时长训练可显式使用超时零收益，但这不等于证明实际游戏发生平局。
